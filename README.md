# WireDroid 1.0.0 — Embedded IDE

GitHub: [MrmaderatorYT/WireDroid](https://github.com/MrmaderatorYT/WireDroid).

[Завантажити APK версії 1.0.0](https://github.com/MrmaderatorYT/WireDroid/releases/tag/v1.0.0).

WireDroid — Android IDE для C/C++ та схем із платами, створена на основі DroidEditorArchitecture. Повний нативний редактор зберігає вкладки, дерево файлів, створення проєктів, налаштування, теми, пошук, історію, Git та експорт. Праворуч відкривається конструктор у темі IDE; панель кнопок прокручується горизонтально.

Версія розробки **1.0.0**, versionCode **1**, application ID `com.ccs.wiredroid`. Основний формат програм — `.cpp`. Користувацькі проєкти й шаблони призначені для embedded-розробки. Внутрішній namespace спільного редактора — `com.ccs.wiredroid`; компілятори користувацьких Java/JVM-програм не входять до APK.

## Створення та робота

На початковому екрані виберіть **Новий проєкт | Приклади**. У режимі прикладів список містить **17 готових проєктів** із програмою, платою та проводами. Кожен створюється в окремій папці; наявний проєкт не перезаписується. Відкрийте **Плати та з’єднання**, виберіть плату та натисніть **Код**, щоб відкрити її програму в нативній вкладці.

Кнопка **Запустити** спочатку зберігає змінені embedded-вкладки. Якщо запис не вдався або файл заблоковано, запуск скасовується з повідомленням. Незбережений текст має окремі контрольні копії, навіть коли AutoSave вимкнений; після відновлення він залишається зміненим буфером до явного збереження. Схеми використовують `schemaVersion: 2` із міграцією попереднього формату, журналом запису та перевіреною резервною копією.

Конструктор дозволяє рухати, повертати й змінювати розмір деталей **25–200%**, вибирати кілька деталей, переміщувати групу, копіювати її з внутрішніми проводами та вирівнювати. Копія плати отримує окремий `.cpp`; прошивку для неї потрібно імпортувати явно. Доступні undo/redo, кольори проводів, прямокутні маршрути, точки перегину та підсвічування електричного ланцюга. У **Проєкт → Схема** пошук за назвою або ID переходить до встановленої деталі й центрує полотно. Межі сцени: 250 деталей, 2000 проводів та 8 плат.

## Три режими плати

| Режим | Виконання | Межі |
| --- | --- | --- |
| C/C++ GPIO | Реальний ARM64 Android процес, Clang, C++17/C11 та libc++ | Узагальнені контакти плати; час Android, програмні переривання й адаптери Arduino |
| AVR MCU | Імпортований Intel HEX виконується як інструкції ATmega328P через AVR8js | Uno/Nano ATmega328P, 16 MHz; GPIO/таймери/PWM/ADC/UART/SPI/TWI/EEPROM та налагодження у віртуальному часі |
| USB | Serial через OTG та завантаження перевіреного HEX за STK500v1 | CDC, CH340, FTDI, CP210x, Prolific; протокол перевірений програмно, фізичне Uno/Nano завантаження ще потребує перевірки |

В інспекторі плати вибираються точний профіль, core, режим, defines, джерела й include paths. **Проєкт → Плати** показує окремі статуси зображення, контактів, GPIO, виробничої збірки, MCU й USB для всіх **339 записів каталогу плат**. Точні AVR-цілі є для Uno та трьох класичних Nano; виконання MCU наразі підтримує ATmega328P. Nano ATmega168 не має цього backend. Для ESP32, RP2040, STM32 та інших сімейств виробничі прошивки й MCU ще не реалізовані.

Android-компілятор працює в режимі GPIO та потребує ARM64 пристрою. AVR-прошивка збирається на комп’ютері за допомогою [локального builder](tools/wiredroid/build-avr-firmware.py), Arduino AVR core 1.8.6 та AVR GCC 7.3, або імпортується як `.hex`. AVR-компілятора всередині Android немає. Реальні ELF/HEX для Uno, Nano, периферії та багатофайлового проєкту з бібліотеками включені в `tools/wiredroid/fixtures/`.

Перед MCU-запуском і USB-завантаженням перевіряються контрольні суми HEX, джерел та параметрів збірки. Зміна `.cpp`, заголовків, профілю, core, defines, sources/exclude/includePaths, C++ standard чи library lock вимагає нової прошивки. Імпорт зовнішнього HEX фіксує поточний стан проєкту, але не доводить, що цей HEX був зібраний саме з цих джерел.

## C/C++ і Arduino-бібліотеки

Типова структура:

```text
circuit.wire.json
wiredroid.json
sketches/uno.cpp
src/display.cpp
src/helper.c
src/boards/uno/driver.cpp
include/display.h
libraries/Counter/library.properties
libraries/Counter/src/Counter.h
libraries/Counter/src/Counter.cpp
```

`src/`, `include/`, файли поряд зі скетчем і потрібні source-бібліотеки входять до плану збірки. `src/boards/<id>/` ізолює код окремої плати. `wiredroid.json` зберігає цілі та дозволяє вибирати джерела, виключення й бібліотеки. Основний entry point — `sketches/<board-id>.cpp`, із `setup()/loop()` або власним `main()` для GPIO. C-файли використовують звичайні C/C++ linkage declarations. `.ino` компілюється як C++ із Arduino.h; автоматична генерація прототипів ще не реалізована.

GPIO має стандартні контейнери, strings/streams/math, винятки та конструктори; Arduino String/Print/Stream/IPAddress із ArduinoCore-API; upstream LiquidCrystal і Stepper; адаптери Servo/Wire/SPI/EEPROM/Serial. AVR використовує реальний Arduino AVR core та звичайні архітектурні бібліотеки; стандартний core має C++11 і не дає автоматично можливості повної Android libc++.

**Проєкт → Бібліотеки** імпортує ZIP із `library.properties`, перевіряє залежності й архітектури, фіксує версію та хеш у `wiredroid-libraries.lock.json`, зберігає кеш і відновлює встановлені пакети без інтернету. Відповідність declared architecture не підтверджує всі периферійні вимоги бібліотеки; GPIO-адаптери й апаратні регістри мають різні можливості. Помилка компілятора відкриває відповідний файл, рядок і колонку в редакторі.

## Електроніка, пристрої й мотори

Вбудований solver розраховує напругу, струм та потужність методом вузлових рівнянь, нелінійних ітерацій і backward Euler. R/C/L, діоди, LEDs, NPN/PNP, N/P MOSFET, джерела, потенціометри, фоторезистори, термістори та ручні аналогові входи мають параметричні моделі. Великі мережі використовують sparse elimination після 96 невідомих, із межею 1024 та бюджетом роботи. Числові тести порівнюють результати з аналітичними й dense-розрахунками; універсальна SPICE-точність не заявляється.

Механічні моделі охоплюють DC-мотор із R/L, back EMF, інерцією й навантаженням; біполярний та уніполярний stepper; A4988 із п’ятьма режимами кроку, sleep/reset/enable та усередненим current limit; позиційне серво; continuous servo; комбінований ESC/BLDC з активацією, throttle, прискоренням і втратою сигналу. Фізичний кут та rpm керують анімацією. Фазова комутація BLDC, точний chopper і теплові захисти драйверів ще не моделюються.

Без запуску важіль серво можна крутити прямо на схемі або повзунком. Під час запуску ним керує програма з урахуванням живлення, імпульсу й навантаження. Потенціометр працює жестом і повзунком. Квадратурний енкодер має ручний кут, rpm або джерело руху іншого мотора; усі A/B переходи зберігаються моделлю, але високочастотне читання native GPIO залежить від частоти опитування.

HD44780, 74HC595, PCF8574, SSD1306 та I²C EEPROM мають перевірені команди й режими, вимоги живлення/return та повідомлення про відсутній пристрій. Модель для кожної конкретної мікросхеми каталогу не є повністю підтвердженим manufacturer emulator.

Каталог включає **2570 записів**: 2569 Fritzing і новий ESC/BLDC блок. **484 прив’язки до 29 сімейств** пройшли структурну перевірку ролей; це параметричні сімейства, які потребують характеристик конкретного SKU. Решта деталей має монтаж, контакти й внутрішні шини; відсутня поведінка вказана в інспекторі та матриці компонентів.

**Перевірити** знаходить нез’єднані контакти, коротке живлення/GND, конфлікти виходів та LED без резистора. Натискання фокусує відповідну деталь. У **Допустимі режими та джерело** можна записати межі напруги, струму та потужності з ручною приміткою або документацією виробника; після цього перевищення виміряних величин дає попередження. Повний supply current серво/ESC/цифрових IC не розраховується.

## Сигнали, Serial і налагодження

Монітор показує кілька каналів, HIGH/LOW, ADC/PWM, фронтовий тригер, період, ширину імпульсу, duty та декодування наявних UART/I²C/SPI фронтів. VCD зберігає часову шкалу, джерело й позначення реконструйованого PWM; MCU-фронти експортуються зі шкалою 1 ps. Буфери й розмір експорту обмежені.

Для AVR GPIO й апаратні периферійні події використовують кількість тактів MCU. Аналогова схема та обмін між кількома MCU узгоджуються квантами до 1 ms; це межа точності їх взаємодії. SPI/TWI працюють на рівні транзакцій із апаратною затримкою, без синтезу всіх електричних фронтів. Serial AVR поки не створює TX/RX waveforms на контактах. GPIO на Android використовує час процесу та реконструкцію PWM.

**Налагодження** дозволяє pause, крок інструкції, continue, reset, breakpoint за byte PC і перегляд r0–r31, SP, SREG, cycles та virtual time. Source-level C++ debugger ще відсутній. Serial Monitor приймає та надсилає дані native GPIO, AVR і під’єднаному USB-порту.

## SPICE та приклади

**Проєкт → Експорт SPICE** приймає числові `.model` D/NPN/PNP/NMOS/PMOS LEVEL=1, зберігає їх і експортує підтримані аналогові примітиви в `.cir`. Непідтримані деталі дають помилку або явно пропускаються з попередженням за вибором користувача. `.include`, `.control`, команди й subcircuits відхиляються. **ngspice всередині застосунку ще не виконується**. [Поточний API і подальша інтеграція](docs/WIREDROID-SPICE-INTEGRATION.md).

17 прикладів доступні під час створення проєкту: Uno blink, кнопка/LED, світлофор, Nano LEDs, ESP32 GPIO blink, servo sweep, potentiometer/servo, RC/ADC, DC/L293D, stepper/L293D, LCD multifile/library, I²C EEPROM, A4988 microsteps, unipolar/ULN2003, ESC/BLDC, quadrature encoder та **реальна AVR Blink-прошивка**. Копії знаходяться в `examples/`; AVR-приклад містить HEX і manifest та запускається без AVR-компілятора Android.

## Збірка, перевірки та ліцензії

JDK 17, Gradle 9.4.1, AGP 9.2.1, SDK/Build Tools 36, NDK 28.2.13676358 та CMake 3.22.1. Повні команди й device-набори в [EMBEDDED_BUILD.md](docs/EMBEDDED_BUILD.md).

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest
node tools/wiredroid/mcu.test.cjs
node tools/wiredroid/electronics.test.cjs
node tools/wiredroid/examples.test.cjs
PLAYWRIGHT_MODULE=/path/to/playwright node tools/wiredroid/platform-browser.test.cjs
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Верифікація окремо показує JVM-тести, числові моделі, браузер із mock bridge, справжній Android C/C++ процес та імпортовану AVR-прошивку. Віртуальний Android display перевіряє WebView/native bridge, а `ide-reliability` запускає повний нативний редактор. Реальний телефон і USB Uno/Nano потрібні для завершення відповідних hardware-сценаріїв. [Звіт 1.7](docs/WIREDROID-1.7-VALIDATION.md).
