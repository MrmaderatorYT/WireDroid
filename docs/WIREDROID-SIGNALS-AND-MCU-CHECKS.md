# Сигнали та перевірка механізму MCU

Оновлено 3 жовтня 2026 року.

## Час і запис

`WireSignals.Timeline.record(board, pin, event, now)` зберігає події MCU з `clock:"virtual"` / `source:"mcu"` без додавання часу браузера. `event.time` — мікросекунди віртуального часу MCU; `cycles` зберігаються за наявності. Android GPIO-процес залишає свій режим часу з прив’язкою до вікна монітора.

Канал має `clock`, `domain`, `source`, `reconstructed`. Прямі MCU GPIO-фронти позначені записаними; PWM, відтворений із команди duty/frequency, позначений реконструйованим. Обмеження за замовчуванням: 4096 подій на канал, 65536 сумарно, 1024 канали. Найстаріші події видаляються; метадані показують кількість збережених подій. Експорт і декодування обмежені 100000 фронтів; надмірне вікно дає конкретну помилку.

## Монітор і декодери

| Метод | Результат |
| --- | --- |
| `metadata(pin)` | Годинник, джерело, реконструкція та retained |
| `range(pins)` | Межі збережених часових міток |
| `measure(pin,start,end)` | Середні periodUs / frequencyHz / highUs / lowUs / duty |
| `trigger(pin,{edge,start,end,level,preUs,postUs})` | Перший rising/falling/any фронт і вікно до/після нього |
| `capture(pins,options)` | Тригер і точки кількох каналів в одному часовому домені |
| `vcdChannels(pins,start,end)` | VCD кількох каналів з годинником і джерелом кожного |
| `decodeUART(pin,options)` | Байти, час, parity/framing/truncated помилки |
| `decodeSPI(options)` | MOSI/MISO слова, чотири CPOL/CPHA режими, MSB/LSB порядок |
| `decodeI2C(options)` | START/repeated START, 7-bit адреса, read/write, bytes, ACK/NACK, STOP |

Існуючі `valueAt`, `eventAt`, `points` та `vcd(pin,start,end)` залишені сумісними. Для віртуального VCD використана шкала 1 ps, щоб передати дробову мікросекундну мітку 16 MHz MCU; це формат експорту, він не додає фізичної точності моделі. Для Android GPIO лишається 1 us. Різні часові домени в одному експорті відхиляються, їх потрібно експортувати окремо. Записані MCU фронти й реконструйований PWM мають окремі позначки у VCD.

UART options: `baud`, `bits` (5–9), `parity` (`none/even/odd`), `stopBits` (1 / 1.5 / 2), `invert`, `start/end`. SPI: `clock` (SCK pin), `mosi/miso`, необов’язковий `select`, `mode` (0–3), `order` (`msb/lsb`), `bits` (1–32), `active` (0/1), `start/end`. I²C: `scl/sda`, `start/end`. Декодери працюють із наявними цифровими фронтами, вони не відтворюють відсутні фізичні сигнали з тексту Serial або абстрактної транзакції Wire. I²C 10-bit адреса визначається як непідтримувана, замість вигаданої 7-bit адреси. UART-повідомлення після обрізаного старту чи до завершення stop bit потребує ширшого часового вікна.

Перевірено: незалежність віртуальних міток від браузера, кілька VCD каналів, відхилення mixed-clock, 62.5 ns фронт, реконструйований PWM, period/pulse/duty, тригери, UART parity/framing/invert, усі чотири SPI режими й обидва порядки бітів, I²C адреса/ACK/NACK/STOP/repeated START, ліміти запису та зміна PWM на звичайний GPIO без зайвого фронту на межі команд. Тест: `tools/wiredroid/signals.test.cjs`. Регресія `devices.test.cjs` також пройшла.

## MCU і асинхронні операції

Перевірка трьох файлів `mcu.js`, `mcu-worker.js`, `avr-runtime.js` виконана послідовно за методикою Bug Hunter: карта потоків → перевірка поведінки → спроба спростування → остаточний висновок. Один підтверджений дефект виправлений: підтвердження попередньої паузи завершувало Promise нового кроку зі старим PC / cycles. Запити й відповіді тепер мають `requestId`; step/reset чекають реального завершення попередньої операції. При паузі під час очікування обміну завершується відповідний попередній запит, без помилкового завершення наступного.

`mcu-runtime.test.cjs` виконує справжній код worker через асинхронні FIFO-повідомлення й перевіряє step/reset/pause, очищення після timeout, pause під час SPI bus reply та порядок двох MCU з квантами 1 ms. До виправлення тест кроку відтворював дефект; після виправлення весь тест пройшов.

`mcu-protocol.test.cjs` перевіряє регістри реального AVR8js механізму:

- UART RX отримує байти `65, 0, 66, 255` у правильному порядку; `rxBusy`, завершення символу, читання UDR і ліміт черги 8192 обробляються коректно.
- SPI чекає відповіді зовнішнього пристрою, а SPIF з’являється після апаратних transferCycles; readback повертає відповідь MISO.
- TWI 100 kHz встановлює address ACK / data NACK у справжніх регістрах після дев’яти SCL тактів, а не одразу після повідомлення браузера.

`mcu.test.cjs` окремо перевіряє справжні скомпільовані Arduino HEX: 100 ms Blink, Timer0 PWM, ADC, UART output, зовнішній ISR, pause/step/breakpoint/reset і EEPROM. Дані RX у цій ітерації перевірені на рівні регістрів; окрема скомпільована UART echo-прошивка ще потребує тесту. Взаємодія кількох MCU узгоджується кожну 1 ms; це визначена межа обміну між ними, а не твердження про повну точність усієї схеми до такту.
